版本：产品 v1。日期：2026-10-16。角色：product。真实 Codex Session ID：`01a1446c-517e-77e0-a876-b5a53f2ae5c1`。本产品属于已授权边界迁移 S7 的公开入口子目标。沿用[主飞书需求](https://applink.feishu.cn/client/todo/detail?guid=9541c1a5-06aa-4762-8a76-293eaa2bf6c9)，不新建业务需求。

## 产品设计

### 用户目标与范围

访问旧团队指南地址的读者应直接看到维护位置已迁移，并能打开 Team 的现有入口或返回 Config Dashboard。Config 公开页只维护入口说明。Team 实际指南由独立的私有任务维护，本页不等待或复制该指南正文。

本次只把 `site/workflow.html` 定义为最小迁移说明页。页面保留原地址，不自动跳转，不提供安装操作、团队状态或账号功能。Config 继续维护基础配置和 Dashboard。团队规则、指南及独立安装由 SuperBeiTeam 维护。

### 页面内容与入口

- 主标题：团队指南已迁移至 SuperBeiTeam。
- 说明：AI Config 继续维护基础配置与 Dashboard。团队规则、指南与独立安装由 SuperBeiTeam 维护。
- 权限提示：SuperBeiTeam 是私有仓库，需要仓库访问权限。无法打开时，请确认当前 GitHub 账号已获授权。
- 页面显示三个入口。生产链接使用原生链接，不要求新窗口或脚本。

| 入口文字 | 生产目标 | 核对结果 |
| --- | --- | --- |
| 返回 AI Config Dashboard | `index.html` | 本仓现有 Dashboard 文件与原返回路径 |
| 打开 Team 指南与安装入口 | [Team README](https://github.com/NBStarry/SuperBeiTeam/blob/main/README.md) | GitHub API 元数据确认 `main/README.md` 为已存在文件；未读取正文 |
| 打开 Team 仓库 | [SuperBeiTeam 私有仓库](https://github.com/NBStarry/SuperBeiTeam) | GitHub API 确认仓库存在、默认分支为 main、private 为 true |

README 是当前可用的指南总入口。后续私有指南可以从 Team 自身入口继续维护。Config 不预先链接未确认存在的文件。

## 架构设计

### 公开边界

公开页不读取或嵌入 Team 私有源码、指南正文、运行数据或认证信息。链接只让读者导航到 GitHub，并由 GitHub 判断权限。本仓不新增 Team 登录、镜像、抓取或状态接口。

生产实现优先沿用本仓现有页面样式和原生 HTML。技术拆分、CSS 复用和无用脚本处理由架构与开发决定。本产品不修改生产 HTML、CSS、JavaScript 或 Dashboard 数据。

### 地址与兼容

保留 `site/workflow.html`，继续服务已有 Dashboard 入口和旧书签。带原片段的地址也应显示迁移提示。现有片段包括 `overview`、`architecture`、`five-roles`、`example`、`checks`、`principles`、`operations`、`limits`；不需要继续维护旧章节内容。返回 Dashboard 的相对路径保持 `index.html`。

本次不扩大到其他历史原型或 workflow 发行目录。现行 Team 指南由远端 Hermes 任务另行制作，公开入口不依赖其未来文件名。

## 验收设计

| ID | 验收条件 |
| --- | --- |
| A1 | 公开迁移页只说明职责迁移与访问要求，不再展示五角色、阶段、返工或团队安装正文，不读取 Team 私有源，不提供团队状态面板或自动跳转。 |
| A2 | 生产页提供返回 Config Dashboard、Team 已存在的 README 指南与安装入口、Team 仓库三个原生链接；链接目标与产品表一致，私有入口明确需要权限，不虚构未来指南路径。 |
| A3 | 桌面 1280px 与移动 390px 宽度均可阅读并操作；文字与按钮不重叠、无遮挡、无横向滚动，链接文字说明目标，键盘可访问真实链接。 |
| A4 | 保留 site/workflow.html 原文件路径；workflow.html 及带既有片段的历史地址仍显示迁移说明；返回入口继续到 index.html。生产旧地址实际运行和部署情况单独记录。 |

| 层次 | 必需证据 |
| --- | --- |
| 自动检查 | 生产页内容与链接检查、无私有读取逻辑、路径存在、原型资产发布校验 |
| 浏览器实际运行 | 实现后的桌面和移动视口截图、无横向滚动、键盘链接访问、原路径和旧片段地址检查 |
| 部署与用户验收 | 部署后的旧 URL 实际可达及用户复核结果；未观察时写未验证，不用本地原型代替 |

产品阶段只核对设计资产与当前入口元数据。开发与独立测试必须对实际候选页面另行验证 A1–A4。私有权限提示不能保证任意 GitHub 账号已有访问权限。

## 实施安排

1. 产品读取现有页面与委派记录，确认 Team 仓库及 README 元数据，交付四节设计、最小离线原型和本仓 manifest。
2. 产品检查资产、前后截图及移动桌面设计后，以本人真实会话发布 product。总管确认该版本后，架构编写实现计划与影响图。
3. 开发只按确认范围更新公开迁移页。独立测试针对同一候选检查 A1–A4，并单列浏览器实际运行、部署和用户验收。
4. 总管关联原飞书需求，汇总 Config 入口与独立 Team 指南的交付情况。产品角色不实施生产页面，不自行确认、不提交或部署。
