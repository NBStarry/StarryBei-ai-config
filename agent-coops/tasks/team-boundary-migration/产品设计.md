## 架构设计

### 本仓边界

基础安装继续维护基础配置链接。`config/manifest.json` 只管理本仓基础资源。旧团队安装参数与 Python 兼容入口只显示迁移说明，不写宿主配置、不下载私有代码，不删除既有安装回执或备份。

全局基础原则要求先读取目标项目规则，遵守该项目当前有效验收正本。不得再把 Config 的冻结 `VERIFY.md` 强制作为所有项目的合并条件。旧项目仍使用自己有效的原流程，其他项目不随本次迁移。

`workflow/v0.1.x`、`workflow/v0.2.0` 及旧 hook/plugin 程序属于冻结兼容资产。开发和测试以迁移前冻结基线核对字节与摘要。文档入口可以说明维护权迁移，不借此更新冻结程序。

### 本项目正式接入

用户已授权两项目接入。Config 的接入文件固定为 `agent-coops/project.json`、`agent-coops/run.py`、`STATUS.md` 和 `agent-coops/hooks/pre-commit`。它们只保存项目入口与 Team 版本引用，不复制 Team 私有实现。总管按 Team 当前已确认架构满足宿主 loader 的安装前置条件，再执行正式接入。bootstrap 文件和源码提交不能证明新版门禁已安装或已经通过。

本产品、后续本仓计划及其 manifest 引用本仓相对路径和本地资产。跨仓正本链接用于追溯，不把 Team 私有 evidence 当成本仓发布资产。接入程序与门禁如何实现由架构角色定义。

### 后续页面边界

`site/workflow.html` 的最终迁移指针保留给后续真实 Hermes Web 指南业务子目标。本产品原型不替代该页面。本次不提前修改生产页面或声称该项完成。

## 实施安排

1. 产品在同一隔离 worktree 交付本文件、[本仓产品 manifest](evidence/config-product-manifest.json)、离线原型和模型证据。本次只写本任务的产品文件。
2. 总管确认本仓产品版本。架构引用该版本编写本仓计划与影响图，并引用 Team 最新已确认架构；设计尚未确认时不把草稿当作有效上游。
3. 开发按确认计划维护基础配置、兼容入口与接入文件。总管完成历史条目读回和在办任务交接。其他项目及其他 owner 状态保持原有效流程。
4. 独立测试核对本仓 A1–A8 与候选摘要，分别记录自动检查、实际运行和用户验收。后续真实 Hermes Web 指南任务接续生产页面迁移指针。
5. 新 loader 安装完成且总管通知后，本产品角色使用自己的真实 `CODEX_THREAD_ID` 正式 publish。本次不伪造 `HERMES_SESSION_ID`，不安装、不部署、不提交，不自行确认产品或任务完成。
