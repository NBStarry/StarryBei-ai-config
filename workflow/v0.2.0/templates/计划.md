# 任务名称计划

## 产品设计

引用产品设计.md及总管已确认的产品版本。保留用户原话、需求来源与授权范围，不在计划中另建产品标准。

## 架构设计

说明技术方案、影响范围、接口、兼容方式和风险。引用架构图与流程图。制作流程图或HTML原型时，先使用free-tokens的opus-5.5；失败才回退astra，并记录原因及最终模型。

## 验收设计

对应产品验收项，列出自动检查、实际运行和用户复核的方法及证据位置。测试角色独立执行，不以开发自检代替验收。

## 实施安排

- [ ] S1 核对已确认版本、实际实现与影响范围
- [ ] S2 完成实现及必要自检
- [ ] S3 独立测试并处理失败项
- [ ] S4 汇总当前版本、全部适用验收项及问题状态，提交最终验收材料

架构角色发布计划，总管确认后进入开发。开发角色先在执行记录写证据，再勾选对应步骤，不改计划正文。发生偏差时交总管分类处理；暂停受影响步骤，其他步骤可继续。
